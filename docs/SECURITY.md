# 防盗号说明

> 一句话结论：**现在的版本是「本机账号」，密码只能挡住室友随手点开，挡不住真攻击。**
> 要做到「谁也盗不走」，必须把账号搬到服务器上（Supabase Auth）。下面是威胁、现在做了什么、以及上线前必须补的清单。

---

## 一、谁能怎么盗你的号

| 攻击方式 | 现在这版会不会中 | 说明 |
| --- | --- | --- |
| 室友用你开着的电脑 | 会 | 浏览器没锁屏，等于账号没锁 |
| 有人导出浏览器的 localStorage | 会 | 本机数据全是明文 JSON，密码只是摘要，但会话 ID 直接能用 |
| 撞库 / 弱密码 | 部分挡住 | 有弱密码黑名单 + 5 次锁定，但没有服务端风控 |
| 钓鱼假登录页 | 会 | 用户自己把密码输到别处，任何系统都难防，只能靠提示和教育 |
| XSS 偷 token | 大幅降低 | React 默认转义、没有 `dangerouslySetInnerHTML`、生产环境加了 CSP |
| 公共 WiFi 抓包 | 看你怎么访问 | 必须 HTTPS；`http://` 下密码虽然不传输（本机校验），但页面可能被替换 |
| 手机/电脑丢了 | 会 | 没有远程下线能力 |

## 二、这一版已经做了的

| 防护 | 实现位置 | 具体做法 |
| --- | --- | --- |
| 密码不存明文 | `src/lib/auth.js` | PBKDF2-SHA256，12 万次迭代 + 16 字节随机盐，只存 64 位十六进制摘要 |
| 弱密码拦截 | `src/lib/auth.js` `strongPassword()` | 至少 8 位、两种字符；拦截 `123456`、`password`、`5201314` 等常见密码；禁止把昵称/学号写进密码 |
| 登录失败锁定 | `src/lib/store.js` `login()` | 连错 5 次锁 5 分钟，锁定期内即使密码正确也拒绝，并提示剩余时间 |
| 会话有效期 | `src/lib/store.js` | 默认 12 小时；勾选「记住我」7 天；过期后强制重新登录 |
| 学号不外泄 | `src/lib/store.js` `maskStudentNo()` | 注册后就打码成 `2023******`，只存在本人资料里，不进公开接口 |
| 数据隔离 | `src/lib/store.js` `sync()` | 聊天、圈子、设置、AI 额度都按用户 ID 分开投影，同机换号不串数据 |
| 前端 XSS | 全站 | 只用 React 文本插值，没有 `dangerouslySetInnerHTML`，用户内容不会被当 HTML 执行 |
| 生产环境 CSP | `vite.config.js` + `public/_headers` | 打包时注入 CSP，Cloudflare Pages 再补 `X-Frame-Options`、`nosniff`、HSTS 等响应头 |
| 删除账号 | 「我的 → 账号」 | 删号会清掉自己的动态、相册、日志、留言、会话和好友关系 |

自测：`node scripts/verify-store.mjs` 里包含「错密码被拒」「连续失败锁定」等断言。

## 三、这一版做不到的（别自己骗自己）

1. **本机账号不是真账号。** 任何人打开 DevTools，都能看到 `localStorage` 里的 `xiangyu.state.v2`，也能直接改出一个已登录会话。密码在这里的作用是「防误触」，不是「防攻击」。
2. **没有远程下线、没有找回密码、没有二次验证。** 忘了密码只能删号重来。
3. **换设备 = 换一个世界。** 同学在他手机上注册，你看不到他，他也看不到你。
4. **没有服务端风控。** 限流只在本机，清掉浏览器数据就重置了。

结论：**要回答「怎么防止盗号」，答案不在前端，在架构。**

## 四、上线前必须补的（Supabase 版）

按重要性排序，前 6 条不做完，别开放注册。

1. **用 Supabase Auth，不要自建密码表。**
   密码交给 GoTrue 处理（bcrypt + 服务端限流），前端拿到的只是 JWT。
2. **邮箱验证后再允许发内容。**
   Supabase 默认会发确认邮件；把「未验证邮箱」的用户限制为只读。
3. **开服务端限流 + 验证码。**
   Supabase 有内置登录速率限制；再在登录入口挂一个 Edge Function，按 IP + 账号双维度限流，失败 5 次要求人机验证。
4. **短 JWT + refresh token 轮换。**
   默认 1 小时 access token；登出时调用 `signOut()` 吊销 refresh token，并清理本地会话。
5. **把 RLS 真正打开。**
   `supabase/schema.sql` 里已经写好策略：私信只有会话成员可读写、学号只有本人可读、`system_settings` 只有 service_role 能改。**部署后必须用两个真实账号互测一遍**。
6. **HTTPS + 安全响应头。**
   Cloudflare Pages 自带 HTTPS；`public/_headers` 已经配好 HSTS / CSP / nosniff / X-Frame-Options。
7. **二次验证（MFA）。**
   Supabase 支持 TOTP：绑定后登录多一步 6 位码，能挡住 90% 的撞库。
8. **设备与会话管理。**
   列出「当前登录的设备」，支持一键踢掉其他设备（Supabase 的 session 表）。
9. **新设备登录邮件提醒。**
   检测 UA/IP 变化，发一封「不是你本人请立即改密」的邮件。
10. **改密 / 找回密码的安全流程。**
    邮件重置 token 一次性、15 分钟过期；改密后强制所有旧会话失效。
11. **审计日志。**
    记录登录成功/失败、改密、删号、发内容，保留 90 天；异常时能回溯。
12. **永远不要把 `service_role` key 放进前端。**
    它绕过所有 RLS，泄露等于全站失守。只放在 Edge Function 的环境变量里。

## 五、普通用户能做的（写进引导里）

- 密码用一句话 + 数字 + 符号，别用生日、学号、昵称
- 公用电脑不勾「记住我」，用完点退出
- 不在别人的页面里输入账号密码
- 发现同学被盗号，先在「朋友」页删好友，再举报

---

## 六、现在就能验证的

```bash
node scripts/verify-store.mjs
```

会跑：错密码被拒 → 连续 5 次失败被锁 → 锁定期内正确密码也进不去 → 解锁后可登录 → 改密后旧密码失效。
