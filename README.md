# 橡遇 XIANGYU · 青科大兴趣同频社交平台

> 在青科，**橡**遇同频的你。

一个给青岛科技大学学生用的校园社交网站：注册登录、进兴趣圈、找搭子、同频匹配、私信聊天。
普通功能**一次 AI 都不调用**，只有你主动点按钮时才可能花钱。

**这里没有示例用户，没有机器人。** 列表里出现的每一个人，都是真的注册过的；没人的时候就是空的。

## 二、账号：只有真人能进

| 项目 | 现在的做法 |
| --- | --- |
| 注册 | 昵称 + 密码 + 年级 / 校区 / 专业 / 学号（选填）+ 兴趣标签 |
| 密码存储 | PBKDF2-SHA256，12 万次迭代 + 随机盐，只存摘要，不存明文 |
| 密码强度 | 至少 8 位、两种字符；拦常见弱密码（`12345678`、`password`…）；禁止把昵称/学号写进密码 |
| 登录 | 昵称 + 密码，摘要对得上才进得去；连错 5 次锁 5 分钟，锁定期内正确密码也拒绝 |
| 会话 | 默认 12 小时有效；勾「记住我」7 天；过期强制重新登录 |
| 昵称 | 同一台设备内唯一，重名会被拒绝 |
| 学号 | 输入后就打码（`2023******`），只有本人看得到 |
| 数据隔离 | 每个账号的圈子、搭子、聊天、设置、AI 额度分开存，共用一台电脑也不串 |
| 前端防护 | 生产环境注入 CSP，`public/_headers` 带 HSTS / nosniff / X-Frame-Options |
| 删除 | 「删除账号」清掉自己的资料、搭子、聊天；「清空本机数据」清掉全部账号 |

**必须说清楚的三件事：**

1. 这是**本机账号**，只存在这台电脑的浏览器里，换设备、换浏览器、清缓存就没了。
2. 没有短信、没有学籍核验，所以「真人」指的是**真的有人注册并记住密码**，不是「验证过是青科大学生」。
3. 同一台设备上注册两个账号，可以互相发私信、互相看到搭子；**不同设备之间目前看不到彼此**——要做到这一点必须接后端（见第十节）。

没有找回密码：忘了就只能重新注册，或者清空本机数据。

> 关于「怎么防止盗号」：本机账号挡得住室友随手点开，挡不住真正攻击。完整的威胁分析、这一版做了什么、上线前必须补的 12 条，见 [docs/SECURITY.md](docs/SECURITY.md)。

## 三、共享后端：让所有人用同一个站

`npm run dev` 只是本地开发。**要大家共用一个站，跑 `npm run server`：**

```bash
npm run build
npm run server        # http://localhost:8787
```

- 同一个 WiFi 的同学，用 `http://你的内网IP:8787` 就能注册、发动态、加好友、私信
- 数据落盘在 `server/data/world.json`，密码用 scrypt 加盐摘要，token 用 HMAC 签名
- 前端启动时会先探 `/api/health`：探到就走共享后端，探不到自动退回本机模式，不会白屏
- 接口：`/api/register`、`/api/login`、`/api/world`、`/api/op`，全部要求 Bearer token，没 token 一律 401
- 自测：`node scripts/verify-server.mjs`（会用两个账号互发动态、点赞、加好友、私信）

**要“所有人”而不只是一个 WiFi：** 把这个 Node 服务放到任意一台能跑 Node 的机器上（Render / Railway / Fly.io 都有免费层，或你自己的云服务器），绑个域名，前面加一层 HTTPS 反代。

上线前必改两样：

```bash
XY_SECRET=一串很长的随机字符串   # 不设会用默认值，等于谁都能伪造 token
PORT=8787
```

注意：这一版的限流只在登录接口做了「5 次锁 5 分钟」，没有验证码、没有邮件验证，**面向公众开放前建议先接入验证码或改成邀请制**。

## 四、兴趣圈：圈子负责分类，搭子负责具体的事

- **8 个圈子**（产品分类，不是用户）：学习考证、运动健身、文艺生活、技术极客、游戏电竞、吃喝玩乐、户外旅行、志愿公益
- **搭子**：`四级搭子 · 每天 50 词 + 一套真题`、`羽毛球搭子 · 双打缺 2 人` 这种，由真实用户发起
- 人数、搭子数都从 0 开始，谁加入谁 +1，不再有虚数

能做的事：搜搭子（标题 / 地点 / 标签 / 圈子名）、按圈子筛、只看我加入的、加入 / 退出（名额进度条、满员置灰）、搭子详情（发起人、时间地点、已上车的人、私信发起人）、自己发起搭子、圈子详情（守则、成员、圈内搭子）。

数据库对应 4 张表（见 `supabase/schema.sql`）：`circles`、`circle_members`、`circle_posts`、`circle_post_members`。

## 五、校内网那套功能

人人网（校内网）真正让人上瘾的不是“聊天”，而是**把自己的生活放上去、再去看别人的生活**。这一版把这条主线补齐了：

| 模块 | 现在能做什么 | 校内网的对应物 |
| --- | --- | --- |
| 新鲜事 | 发文字 / 最多 9 张图 / 心情，点赞、评论、删除；「好友新鲜事 / 全校新鲜事」两种范围 | 状态 + 新鲜事 |
| 个人主页 | 封面 + 头像 + 资料 + 统计；动态 / 相册 / 日志 / 留言板 四个 tab；来客会被记一次访客 | 个人主页 |
| 好友 | 加好友、通过 / 忽略申请、删除好友、按昵称/专业/兴趣找人；同校区 + 同专业 + 共同兴趣 + 共同好友加权推荐 | 好友 / 可能认识的人 |
| 相册 | 建相册、批量传图（自动压到 900px）、图注、点开看大图、单张删除、删相册 | 相册 |
| 日志 | 写长文（8000 字）、列表、详情、点赞、评论、删除 | 日志 |
| 留言板 | 去别人主页踩一脚，留言按时间倒序 | 留言板 |
| 访客 | 进别人主页会留记录，主页统计里显示访客数 | 访客记录 |

照片只存在本机浏览器（localStorage），不会上传到任何服务器；一张压到 900px、约 60–120KB，浏览器总共约 5MB 额度。

功能划分参考了一批开源校园社区项目（[school_wall](https://github.com/Jay1023CN/school_wall)、[campus-example](https://github.com/oddfar/campus-example)）：它们几乎都围绕「动态 + 评论 + 私信 + 审核」做；这里只借鉴产品结构，没有照搬它们的后端技术栈（SpringBoot / Vue / uni-app）。

## 八、本地运行

需要 Node.js 18 以上（本项目在 Node 24 下验证通过）。

```bash
cd E:\网站
npm install
npm run dev              # 开发，默认 http://localhost:5173
npm run build            # 打包到 dist/
npm run preview:dist     # 预览打包结果，http://127.0.0.1:4173
node scripts/verify-store.mjs   # 跑一遍数据层自测（不需要浏览器）
```

> 打包依赖 esbuild，需要能正常启动子进程。

`verify-store.mjs` 会真实地注册两个账号、发搭子、发私信、删账号，断言「没有预置用户」「错密码进不去」「甲能收到乙的未读」等 16 条行为。

## 九、为什么它不容易烧钱

| 环节 | 做法 | AI 调用 |
| --- | --- | --- |
| 注册 / 登录 / 浏览 / 搜索 | 本机逻辑 + 数据库查询 | 0 次 |
| 私信聊天 | 共享会话存储（正式版走 Supabase Realtime） | 0 次 |
| 兴趣同频 | Jaccard + 重叠系数的混合相似度 | 0 次 |
| 随机匹配 | 队列 + 随机抽取 | 0 次 |
| 深度同频 | 4 项加权评分（兴趣 50 / 话题 20 / 偏好 15 / 深度 15） | 0 次 |
| 推荐理由 | 模板字符串拼装 | 0 次 |
| 破冰话题 / 兴趣总结 | **只有点按钮**才走后端 Edge Function | 1 次 / 次 |

后端还有四道闸门（`supabase/functions/ai-assist/index.ts`）：单用户每日次数、单次冷却、全站每日调用上限、全站每日预算；命中缓存不重复扣费；超限时返回本地模板兜底。

## 十、诚实清单：哪些是真的，哪些还没接

**已经跑通（本地真实可用）**

- 注册 / 登录 / 改密 / 删号，PBKDF2 摘要校验，错密码进不去
- 14 个页面、响应式（桌面 / 平板 / 手机）
- 新鲜事：发文字/图片/心情、点赞、评论、删除、好友/全校两种范围
- 个人主页：动态 / 相册 / 日志 / 留言板 四个 tab，访客记录
- 相册：建相册、批量传图（压缩）、图注、大图、删除
- 日志：写长文、列表、详情、点赞、评论
- 好友：申请 / 通过 / 删除、找同学、按同校区·同专业·共同兴趣推荐
- 兴趣圈全流程，人数和搭子数都是真实计数
- 同一台设备两个账号之间：能看到彼此、能互加好友、能私信、能互相留言
- 匹配三种算法真实计算，分数随标签改变
- 空状态处理，不会出现「假人」

**还没接（不要当成已完成）**

- **共享后端只有单机版**：`npm run server` 后同一个服务器上的人是互通的，但服务器还没部署到公网，也还没做多实例/数据库
- 没有接 Supabase：`supabase/schema.sql` 与 Edge Function 已写好，但**没有在真实项目上执行过**
- AI 面板是**本地模板演示**，没有真的请求 DeepSeek
- 没有域名：`docs/DEPLOY.md` 写了静态托管步骤，服务端部署还要另找一台机器
- 没有短信 / 学籍核验，也没有找回密码
- 服务端限流只有「登录 5 次锁 5 分钟」，没有验证码；照片存在 world.json 里，人多了会撑大

## 十一、下一步

要让「所有人打开就能用」，还差最后三件事：

1. **把 `npm run server` 部署到公网**（Render / Railway / Fly.io 免费层都行），设好 `XY_SECRET`，前面加 HTTPS
2. **把数据从 JSON 文件换成数据库**（正式库用 Postgres，就是 `supabase/schema.sql` 那套表；或先用 SQLite）
3. **加验证码 + 邮箱验证**，再开放注册

如果要走全托管，也可以按 `docs/SUPABASE.md` 把 `src/lib/store.js` 换成 supabase-js（表名、字段已经对齐），前端不用改页面。
